# Create an explainer

Use the bundled CLI at `python <plugin-root>/scripts/explainer.py` (the plugin root is `../..` from this file). Keep the creative decisions and review in the chat. If no creator profile exists, run the [setup skill](../setup/SKILL.md) first.

## Short-form video safe zones

For Facebook Reels, use a 9:16 canvas at 1080 × 1920. Follow the supplied Reels layout guide: reserve the top 250 px and bottom 250 px for interface overlays, leaving the central 1420 px as the working safe area. Treat this as a conservative layout template, not a guarantee that every device or placement uses identical UI bounds.

Reels also place a vertical action rail on the right, with controls such as like, comment, and share. Keep the presenter’s face, captions, labels, and other essential content clear of that rail; do not assume the whole central band is unobstructed. Apply these bounds while planning every portrait scene, including motion paths and elements that enter during animation. If the user supplies a platform-specific guide, follow that guide. During preview review, compare the composition with the intended platform UI, adjust anything that could be covered, and reapprove the storyboard before final rendering. A prompt alone does not guarantee pixel-level compliance.

## Film workflow

1. Ask for the topic, target audience, desired length, and any facts or sources the user wants included. Infer reasonable defaults from the request. Research claims when facts could have changed. Write a short script in the saved language and speaking style, with one paragraph per scene. Show it in chat and wait for the user's approval before generating narration.
2. `init` a project under the saved output folder, then write the approved script to `script.txt`. Never overwrite an existing project or source media. If the user brings a recording, `attach-voice` it. If they selected ElevenLabs, run `synthesize` only after the script is approved and a configured voice ID and API key are available. The user's recording or selected TTS output is the film's timing source.
3. Run `transcribe` to create `words.json` with word timestamps; `import-words` supports a reviewed external word-timing file. Check that the transcript matches the script. Run `storyboard` to align paragraphs, then turn the result into a shot plan rather than accepting paragraph cards as the finished storyboard. For every scene, specify the idea being explained, the concrete visual that proves it, the visual cues and their narration word/time, the presenter pose, and how the composition changes. `visual_cues` use project-owned image paths plus global `start`/`duration` seconds and optional normalized `x`, `y`, `width`, and `height` (0–1). Separate cues stage a sequence of visual reveals. Use one everyday analogy for an abstract concept, or a faithful walkthrough for a real product. Keep on-screen copy short and avoid repeating full narration sentences when captions already show the words. Verify labels and numbers against sources. Show a frame-by-frame visual plan in chat and wait for an explicit yes before `approve`.
   For a graphic with multiple parts, keep its combined PNG as the cue asset and place transparent PNG crops plus a `manifest.json` with each crop’s filename and original `x`/`y` origin in a sibling `<asset-name>.layers/` folder. The renderer stages those parts with separate GSAP entrances in their original layout; avoid baking motion graphics into one flattened image. In portrait scenes, give the visual enough scale to read on a phone and keep it clear of the presenter and Reels controls.
4. Run `render --preview`. Display the Engine-rendered preview and ask for specific revisions. Review the whole contact sheet and sample scene middles, not only opening/closing frames. Check that the supporting visual changes as the narration advances, each new element lands on its cue, no scene holds a complete slide for most of its duration, and the presenter does not cover the subject. Editing the storyboard invalidates its approval hash until reviewed again. Once accepted, run `render` for the full file, then `check` and `contact-sheet`; inspect the contact sheet in chat. Use `sync-check` when faster-whisper is available to compare rendered speech with the source. Deliver the MP4 path and the editable Studio and Engine project folders in chat. Use `render-legacy` only to compare against the old Studio compositor. If a custom avatar is requested, follow the [avatar skill](../avatar/SKILL.md) before rendering. For a portrait cut, render `render --portrait --preview`, review its layout, then render `render --portrait`. For a new take, run `retime` into a new project and review the new storyboard.

Only the user approves the script and storyboard. The agent may prepare files and run read-only checks while waiting. If a render fails, report the exact failed step; do not call the film complete. Engine-backed renders use Rhubarb phonetic cues when configured and map them to the bundled five mouth states; otherwise they use voice loudness. Obtain rights to user-supplied music, images, logos, and voice recordings before publication.
